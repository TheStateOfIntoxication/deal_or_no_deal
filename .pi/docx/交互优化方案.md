# 交互优化方案（v1.5）

**文档性质**：表现层（UI / 反馈 / 信息展示）设计说明
**规则权威**：`.pi/docx/需求文档.md` v1.1 —— 本文与规则冲突时，以规则文档为准
**状态**：优化 1–3 已实现（v1.2）；v1.3 补「结算揭晓 + 不自动重开」；v1.4 补「开局摇奖」；v1.5 补「提前锁定大奖」与「报价算法修订」。优化 1 采用 **A（≥900px 内联条）+ C（<900px 底部抽屉）** 响应式切换，B 的 0.9s 揭示前置保留；概率文案沿用「拿到 {顶奖金额} 的概率」

## 1. 问题诊断

| # | 现象 | 根因 | 业务影响 |
| :- | :--- | :--- | :--- |
| 1 | 银行家报价弹窗遮住刚开出的箱子金额 | 全屏遮罩 + 背景模糊，把「开箱 → 金额 → 报价」的情绪链条切断 | 玩家在决策瞬间看不到自己刚送走了多少钱，Deal / No Deal 缺乏依据 |
| 2 | 不同金额的开箱反馈完全一样 | 反馈只有一行金额文本，没有分级；也没有可持续追踪的处境指标 | 开掉 $1,000,000 与开掉 $1 的体感相同，节目张力消失 |
| 3 | 玩家箱混在箱池里 | 玩家箱与可开箱同区域、同视觉权重 | 「我的箱子」是全局最重要的情绪锚点，被稀释后归属感弱 |

## 2. 优化 1：银行家报价窗口（已按 A + C 实现）

> **决策**：A（≥900px 内联条）+ C（<900px 底部抽屉）响应式切换；B 的 0.9s 揭示前置保留。
> 实现：`src/views/game/components/OfferPanel.vue`（替换遮挡式 `OfferDialog`，后者已删除）。

### 2.1 设计原则

1. **不切断因果**：报价出现时，刚开的箱子与金额必须仍在视野内。
2. **决策聚焦但不掠夺信息**：报价是「选择」，不是「打断」。
3. **移动端不牺牲信息**：小屏也要能同时看到报价与台面。

### 2.2 方案 A｜顶部「银行家来电」条（推荐桌面）

```
┌──────────────────────────────────────────────────────────────┐
│ 状态栏：轮次 3/9 · 剩余 11 箱 · 百万箱 ×2        🔊  [再来一局] │
├──────────────────────────────────────────────────────────────┤
│ ☎ 银行家报价  $186,000      [ Deal 接受 ]  [ No Deal 拒绝 ]   │ ← 固定条，无遮罩
│   本轮已开：#4 $750,000 · #9 $1 · #17 $50,000                  │
├───────────────────┬──────────────────────────────────────────┤
│  我的箱子 #07      │  剩余 11 个箱子（7 列网格，全部可见）        │
│  顶奖概率 18.2%    │   [ 3 ] [ 5 ] [ 6 ] [ 8 ] [ 10 ] [ 11 ]   │
│  ▓▓▓▓░░░░░         │   [ 12 ] [ 13 ] …                          │
│  金额板（划线）     │                                            │
└───────────────────┴──────────────────────────────────────────┘
```

- 报价条替换提示行，位于状态栏与主区之间；不做遮罩、不模糊。
- 条内左侧为报价额，右侧为 Deal / No Deal；副行显示「本轮已开」摘要。
- **优点**：信息零损失；最接近真实节目（电话响起时箱子仍在台上）；实现最轻（报价面板内联在台面顶部，不动状态机）。
- **缺点**：报价额的冲击力弱于大弹窗 → 用 3xl 字号、金色描边、一次性脉冲动画补偿。
- **成本**：约 1 个组件 + 布局调整。

### 2.3 方案 B｜揭示序列 + 弹窗（当前保底方案）

```
点击第 6 个箱子
  → 箱位翻转、金额放大、分级音效与闪光（0.9s）
  → ☎ 铃声，弹窗自下而上出现，内含「本轮已开」三张金额卡
```

- **优点**：改动最小（0.9s 前置揭示已在 v1.2 实现，只剩「本轮已开」区块）；弹窗聚焦感强。
- **缺点**：决策时仍看不到台面全貌，需要把信息「塞回」弹窗；遮罩使情绪连续性弱于 A。
- **成本**：最低。

### 2.4 方案 C｜底部抽屉（推荐移动端）

```
┌──────────────────────────────┐
│  台面（上半部 60% 仍可见）      │
│  [3] [5] [6] [8] [10] …      │
├──────────────────────────────┤
│ ☎ 银行家报价   $186,000       │ ← 抽屉上滑，占 34% 高
│  本轮已开：$750,000 · $1 …    │
│  [ Deal 接受 ] [ No Deal ]   │
└──────────────────────────────┘
```

- **优点**：兼顾聚焦与可见；移动端符合原生交互习惯。
- **缺点**：桌面宽屏上下分割，金额板区域可能被压缩。

### 2.5 对比与推荐

| 维度 | A 顶栏条 | B 弹窗 + 序列 | C 底部抽屉 |
| :--- | :--- | :--- | :--- |
| 信息保留 | ★★★★★ | ★★★ | ★★★★ |
| 节目感 / 冲击力 | ★★★★ | ★★★★★ | ★★★★ |
| 实现成本 | 低 | 最低（已做 70%） | 中 |
| 移动端体验 | ★★★ | ★★ | ★★★★★ |

**推荐：A（≥900px）+ C（<900px）用同一组件响应式切换，并保留 B 已实现的 0.9s 揭示前置。**

> 无论选哪个方案，「开箱 → 金额亮相 0.9s → 报价」的节奏都保留（v1.2 已实现）。

## 3. 优化 2：概率 HUD + 开箱分级反馈（已实现）

### 3.1 指标定义

**顶奖概率 P = 剩余顶奖项数 ÷ 剩余箱子数（含玩家箱）**

- 含义：坚持到底（不 Deal）时，玩家箱开出顶奖的概率。
- 示例（k=2，26 箱）：开局 7.7% → 开掉 6 个非顶奖后 10.0% → 若开掉 1 个顶奖则 5.3%。
- 高 k 时上限更高：k=13 开局 50%，终局两箱均为顶奖的概率约 24%（见需求文档 R-11.2）。

**为什么不只用「剩余均值」**：均值是理性决策指标，但情绪弱——k=2 开局均值 $169,939，开掉一个箱子只变动几千美元，玩家感知不到；顶奖概率是「希望值」，每次开箱波动 1–10 个百分点，能直接驱动情绪。

**为什么不显示「顶奖还在不在」布尔值**：信息量太低，且概率天然包含「还剩几个顶奖 / 还剩几箱」。

### 3.2 位置与形态

采纳「固定区域高亮」的思路，并绑定到**玩家箱舞台卡**——概率是「我的箱子」的属性，绑在箱子上比放在金额板顶部更有归属感：

```
我的箱子
   #07
  ┌────┐
  │ ?  │
  └────┘
拿到 $1,000,000 的概率
  18.2%          ← 大号金色数字
 ▓▓▓▓░░░░░       ← 概率条
剩余顶奖 2 个 · 剩余 11 箱
剩余区间 $1 – $1,000,000
[顶奖概率已超 1/4]  ← 里程碑徽章（≥25/50/75% 出现）
```

### 3.3 开箱分级（解决「效果一样」）

**分位定义**：金额在金额池中的累计分位 =（池内 ≤ 该金额的项数）÷ 池内项数。
选分位而非绝对金额，是因为 k 变化会让池子量级完全不同（k=2 池最小 $1，k=13 池最小 $750），绝对阈值会失真。

| 分级 | 分位 | 名称 | 色调 | 音效 | 视觉反馈 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `disaster` | ≥ 0.75 | 重击 | 红 | 110Hz 锯齿二连击 | 全屏红闪 + 台面抖动 + 箱位红框 + 「!」角标 |
| `bad` | ≥ 0.50 | 不妙 | 橙 | 下滑双音 | 橙色内闪 + 橙框 |
| `neutral` | ≥ 0.30 | 平稳 | 蓝灰 | 单短音 | 无全屏反馈 |
| `good` | < 0.30 | 好签 | 绿 | 上行双音 | 绿光 + 绿框 |

阈值集中在 `src/config/presentation.ts`，与规则配置分离。

### 3.4 节奏

| 时间 | 事件 |
| :--- | :--- |
| 0 ms | 点击箱子 → 金额揭示 → 分级音效 + 全屏闪光 + 台面抖动（仅 disaster） |
| 0–900 ms | 「刚刚开出 #12 · $300,000 · 重击」胶囊条出现，玩家看清结果 |
| 900 ms | 电话铃声 → 报价面板（A/C）或弹窗（B） |

### 3.5 里程碑

P 跨过 25% / 50% / 75% 时在舞台卡显示金色徽章（不弹窗打断）：

- ≥25%：顶奖概率已超 1/4
- ≥50%：顶奖概率已过半
- ≥75%：顶奖大概率在你手里

### 3.6 顺带解决的隐患

- 报价弹窗遮住金额后无处回看 → 新增常驻胶囊条「刚刚开出」。
- 金额板划线保留（重复顶奖逐行划，R-9.6 不变），箱位按分级着色。

### 3.7 结算揭晓（到手奖金档位，v1.3）

结算是最需要仪式感的一刻，分三段推进：

| 时机 | 表现 |
| :--- | :--- |
| 0 ms | Deal / 终局后立即进入**悬念**：舞台卡显示「正在打开你的箱子…」+ 呼吸光晕；台面上未被玩家打开的箱子金额暂不展示，避免提前剧透 |
| 1.2 s | 持有箱**翻牌** → 按「到手奖金档位」播效果；同时揭开台面其余金额 |
| 2.4 s | 弹出结算面板（此时才显示最终奖金、持有箱、历史最高） |

到手奖金档位（按奖金在池内的累计分位，方向与“开箱分级”相反）：

| 档位 | 判定 | 音效 | 视觉 |
| :--- | :--- | :--- | :--- |
| `jackpot` | 奖金 = 顶奖 | 五音上行 fanfare | 金色全屏辉光 + 舞台卡金框 |
| `big` | 分位 ≥ 0.75 | 三音上行 | 绿色辉光 |
| `normal` | 分位 ≥ 0.4 | 双音 | 蓝色内闪 |
| `small` | < 0.4 | 下行双音 | 冷色内闪 |

结算面板新增：档位徽章（顶奖到手！/ 大丰收 / 落袋为安 / 小有收获）+ 「你带走的箱子 #n · 金额」行（交换后显示实际带走的箱号）。

**不自动重开**：结算面板提供两个动作：

- 「完成」：只关闭面板，保留最终牌面与金额，不重置本局；
- 「再来一局」（面板内或顶部按钮）：才回到摇奖开新局。

结算画面本身就是结果展示页，玩家可以慢慢看完再手动开新局。

阈值与时长在 `src/config/presentation.ts`：`PAYOUT_BIG_SHARE`、`PAYOUT_NORMAL_SHARE`、`FINAL_REVEAL_MS`、`RESULT_PANEL_DELAY_MS`。

### 3.8 开局摇奖（玩家参与，v1.4）

**问题**：k 由后台静默随机，玩家对“本局有几个百万箱”没有任何感知与参与。

**设计：金球盲选**

```
┌──────────────────────────── 摇出本局的百万箱数量 ─────────────────────────────┐
│  金球里藏着本局的百万箱数量（2–6 个）。百万箱越多，顶奖越多，但小金额会被移除。     │
│                     选一个试试手气。                                            │
│                                                                                │
│           ( ? )      ( ? )      ( ? )      ( ? )      ( ? )                    │
│                                                                                │
│                            点一个金球                                           │
└────────────────────────────────────────────────────────────────────────────────┘

点击后：
           ( ×4 )      ( ×2 )      ( ×6 )      ( ×3 )      ( ×5 )
                    本局百万箱 ×4
                  桌上最低金额 $10            [ 开始游戏 ]
```

- 开局进入独立摇奖场景（此时台面不渲染）；5 个金球对应配置区间 2–6 的一个 k，位置已打乱。
- 点一个球 → 被选中的球放大发光显示 `×k`，其余球同时揭示（灰暗）——“你本来可能抽到 6”。
- 结果区显示「本局百万箱 ×k」+「桌上最低金额 $X」：k 越大，小金额被移除得越多，让玩家直观看到代价。
- 点「开始游戏」才进入台面，**不自动开局**；「再来一局」重新回到摇奖，每局都有仪式感。

**为什么是盲选而不是转盘/滚轮**：盲选同时具备「选择动作（参与感）+ 即时揭示（悬念）+ 其余球揭晓（后悔/庆幸）」，一次点击完成、没有等待；球位由洗牌决定、值对玩家不可见，公平性等价于系统随机（R-4.1.7）。

**区间为什么定 2–6（趣味优先）**：

| k | 金额池最小项 | 单箱顶奖概率 | 终局两箱皆顶奖 |
| :- | :--- | :--- | :--- |
| 2 | $1 | 7.7% | 0.3% |
| 4 | $10 | 15.4% | 1.8% |
| 6 | $50 | 23.1% | 4.6% |
| 7 | $75 | 26.9% | 6.5% |

- 2–6 之间有 5 个金球，抽奖有花样；同时最差结局仍低到 $1–$50，早期 Deal 仍有吸引力。
- k ≥ 7 起下行风险快速变小（最小项 ≥ $75、单箱顶奖 > 26%），Deal 决策基本失去意义，所以默认区间不再放宽（配置仍可到 13）。

**实现**：`GameEngine.createKDraw()` 返回区间的打乱排列，`GameEngine.start(k)` 接受摇奖结果并校验（非法值拒绝开局）；摇奖期间台面不渲染，引擎不启动。

### 3.9 提前锁定大奖（v1.5）

**问题**：所有低于顶奖的箱子开完后，玩家箱必定是顶奖，但旧实现仍要求开完本轮、等报价、再做 Deal / No Deal 决策。

**规则**（需求文档 R-5.2.7 / R-7.1.3 / R-11.2）：

- 触发：剩余金额集合**全部相等**（等价于玩家箱金额被唯一确定）
- 行为：**立即结算**该金额并结束；本轮剩余开箱配额不再要求；不产生报价、不进入交换
- 表现：沿用结算揭晓节奏（1.2s 悬念 → 翻牌 → 档位效果 → 结算面板）；结算面板显示「提前锁定（剩余箱子金额已确定）」，命中顶奖自动 jackpot 徽章 + 金色辉光
- 状态栏「本轮还需开 N 箱」在结算时归零，不残留配额提示

**实现**：`GameEngine.settleIfCertain()` 在选箱后与每次开箱后调用，判定成立即把 `decidedBy` 记为 `certainty`。

### 3.10 报价算法修订（v1.5）

**问题**：旧公式 `均值 × 乘数`。当剩余金额整体偏高（例如只剩 3×$1M + $750k），均值被大奖抬高但乘数只有 0.5–0.6，报价只有四十多万——与“桌上几乎全是顶奖”的直觉严重不符。

**新公式**：`报价 = 剩余最小值 + (参考锤点 − 剩余最小值) × 乘数`（需求文档 R-6.1.5）

- 只对“**高于最差结果的上行空间**”折价，最差结果不打折
- 天然满足边界（min ≤ 报价 ≤ 锚点 ≤ max），下行风险大时仍保留银行家折价
- 中后期默认乘数同步上调：`0.15 / 0.21 / 0.28 / 0.37 / 0.48 / 0.60 / 0.72 / 0.83 / 0.92`（RMS 另配一套）

新旧对比（默认均值模式）：

| 剩余金额 | 均值 | 旧报价（第 6 / 9 轮） | 新报价（第 6 / 9 轮） |
| :--- | :--- | :--- | :--- |
| 3×$1M + $750k | $937,500 | $469k / $825k | **$863k / $923k** |
| 4×$1M + $100k | $820,000 | $410k / $722k | **$532k / $762k** |
| $1M + $750k | $875,000 | $438k / $770k | **$825k / $865k** |
| $1M + $100 | $500,050 | $250k / $440k | **$300k / $460k** |

最后一行说明：下行风险极大时报价仍然明显低于均值，早期博弈张力不变。

## 4. 优化 3：玩家箱分离（已实现）

### 4.1 方案对比

| 方案 | 做法 | 优点 | 缺点 |
| :--- | :--- | :--- | :--- |
| A 纯重排 | 玩家箱从 26 格删除，其余自动补位 | 干净 | 每次开箱格子跳动，位置记忆丢失 |
| B 固定槽位 + 空位占位 | 保留 26 槽，玩家箱槽位显示「已取走」 | 布局稳定 | 玩家箱仍在箱池区域内，与诉求不符 |
| C 舞台卡 + 从池中移除（**采用**） | 玩家箱进独立舞台卡，网格只留非玩家箱 | 归属感最强、信息分层清晰 | 每次开箱会有轻微重排 |

采用 **C**。为降低重排干扰：已打开的箱子保留原位显示金额（只标记「已开」，不再可点），只有玩家箱离开网格。

### 4.2 交互细节

| 时机 | 表现 |
| :--- | :--- |
| 选箱后 | 网格 26 → 25；舞台卡淡入 + 轻音效，显示箱号与顶奖概率 |
| 开箱中 | 网格只显示非玩家箱；舞台卡概率实时更新 |
| 终局 | 网格仅剩 1 个箱子 + 舞台卡 1 个箱子，交换决策一目了然 |
| 结算 | 舞台卡翻牌显示玩家箱金额，并按分级着色 |
