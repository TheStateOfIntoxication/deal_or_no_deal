# 银行家计划与 AI 设计（v1.4 · P0 已实现）

**状态**：P0（纯前端启发式计划 + 修正明细）已落地；银行家档案注册表已预留；P2（后端 LLM）未实现。规则已回写 `需求文档.md` v1.17 §14.4/§14.6。
**范围**：优化点 2——银行家按局面制定计划、故意压价、拒绝补偿、最后通牒，并为后续 AI 接入留接口。
**依据**：`需求文档.md` v1.17 §6（R-6.1–R-6.4）与 §14.4；`银行家设计.md`、`玩法卡牌与角色设计.md`。
**硬约束**：不改变 R-6.3 边界、R-6.1.5 公式、R-6.4 的怒气 ≤6% / 恐惧 ≤8% / 乘数钳制 [0,1]；所有影响报价的修正必须在界面明示；AI 不得直接产出金额。

---

## 1. 现状与问题

v1.4 的银行家只有两层：

- 基础乘数曲线（按轮次）；
- 怒气压价（≤6%）+ 恐惧加价（≤8%），台词按“信心高低/怒气档位”随机。

问题：

1. **可预测**：同一轮、同一剩余池的报价几乎固定，玩家学会“第 5 轮大约 48%”后惊喜减少。
2. **没有“计划”**：银行家不会因为“你刚拒绝我”而换策略，只会线性加怒气。
3. **台词与数值脱节**：台词随机，玩家感受不到“他在设套/他在让步”。
4. **AI 无处接入**：没有“只做决策、不做数值”的接口边界。

---

## 2. 设计目标与非目标

**目标**

- 每轮报价前，银行家先选一个**可见的计划**（压价/补偿/慷慨/最后报价/常规），再算金额；
- 计划有明确触发条件、上限、冷却，**可解释、可复现、可关闭**；
- 为 LLM 留出 `BankerBrain` 接口：AI 只选计划 + 措辞，数值仍由确定性管线计算；
- 保持现有公平性：报价仍在 [最小值, 锚点] 内，所有修正明示。

**非目标**

- 不做“会作弊的 AI”（读取玩家箱金额、动态改概率、改金额池）；
- 不让 LLM 直接给报价数字；
- 不在 P0 引入网络依赖；
- 不做强化学习训练（P2 之后再说）。

## 3. 统一报价修正管线（核心）

### 3.1 公式

```text
base   = curve[round]                                   // R-6.2.3
fear   = clamp(0.10 × (pTop − 0.10), 0, 0.08)           // R-6.4.3
rage   = 0.06 × rage / 100                              // R-6.4.2
plan   ∈ [−0.04, +0.04]                                 // 本设计
persona∈ [−0.03, +0.03]                                 // 角色
audience∈[−0.02, +0.02]                                 // 从众

m_eff  = clamp(base + fear − rage + plan + persona + audience, 0, 1)
offer  = floor( clamp( lower + (anchor − lower) × m_eff, lower, upper ) )
```

- `lower` / `upper` = 剩余金额最小值/最大值；`anchor` = 均值或 RMS（R-6.1.2、R-6.1.4）。
- 先按 R-6.3.6 边界钳制，再按 R-8.5 floor 到分，最后再钳制一次（与现有实现一致）。
- `plan` 只加在**乘数**上，不直接加金额；因此不会突破“报价不超过锚点”的结构。
- 任何来源为 0 时不展示；非 0 时必须在 `offerMeta.breakdown` 与界面标签中出现。

### 3.2 上限与叠加规则

| 来源 | 上限 | 说明 |
| :--- | :--- | :--- |
| 怒气 `rage` | −6% | 沿用 R-6.4.2，不放大 |
| 恐惧 `fear` | +8% | 沿用 R-6.4.3，不放大 |
| 计划 `plan` | −4% ~ +4% | 低球最多再叠加 −4%，总压价 ≤10% |
| 角色 `persona` | ±3% | 稳重惩罚 / 从众情绪 |
| 观众 `audience` | ±2% | 仅从众 |
| 最终 `m_eff` | [0, 1] | R-6.4.4，最后一道闸 |

- **互斥**：`rebate` 与 `lowball` 不能同轮；`finalPush` 只出现在第 9 轮；`generous` 与 `rebate` 不同轮。抽样时若同时命中互斥项，按权重保留一个，另一个本轮不参与。
- **总压价**：`rage + lowball ≤ 10%`；若同时存在角色惩罚，总压价仍以 `m_eff ≥ 0` 为最终边界，但界面会同时显示三项，避免“暗扣”。
- **重复保护**：同一计划不得连续出现 3 次；第 3 次强制 `steady`（`rebate`/`finalPush` 例外）。
- **空池/单箱**：剩余金额全等时直接提前结算（R-5.2.7），不进入报价，计划系统不参与。

### 3.3 `offerMeta` 扩展

```ts
interface OfferBreakdown {
  base: number          // 曲线值
  fear: number          // +，非负
  rage: number          // −，存正数幅度
  plan: number          // 计划增量，可正可负
  persona: number       // 角色增量
  audience: number      // 观众增量
  effective: number     // m_eff
  clamped: boolean
}

interface BankerOfferMetaState {
  fear: number
  ragePenalty: number
  confidence: number
  breakdown: OfferBreakdown
  plan: BankerPlanState    // 计划 id / delta / 文案 key
}
```

`OfferPanel` 在现有“恐惧 +x% / 怒气 −y%”旁增加“计划 −z% / 角色 ±a% / 观众 ±b%”，用 tooltip 解释；不改变 Deal/No Deal 布局。

## 4. 状态特征（BankerContext）

| 特征 | 类型/范围 | 来源 | 用途 |
| :--- | :--- | :--- | :--- |
| `round` | 1–9 | 引擎 | 曲线、终局判断 |
| `remainingCount` | 1–26 | 快照 | 风险 |
| `openedCount` | 0–24 | 快照 | 局面阶段 |

| `topPrizeRemaining` | 0–k | 快照 | 戏剧性 |
| `cv` | ≥0 | 标准差/EV | 风险 |
| `offerRatio` | 0–1+ | 当前报价（或假设报价）/EV | 接受模型 |

## 5. 计划系统

### 5.1 计划表

| 计划 | `plan` 增量 | 触发条件（全部满足） | 次数/冷却 | 台词方向 |
| :--- | :--- | :--- | :--- | :--- |
| `steady` | 0 | 默认 | — | 常规施压/闲聊 |
| `lowball` | −2% / −3% / −4% | `topProb ≤ 10%`、`rage ≥ 33`、`round 4–8`、上轮未用 lowball | 每 2 轮最多 1 次 | “这次我只给这么多，因为你一直在拒绝我。” |
| `rebate` | +2% / +3% / +4% | `lastRejected = true`、`rejectStreak 1–3`、`round ≤ 8`、上轮未用 rebate | 每次拒绝最多 1 次 | “上次是我小气，这次补给你。” |
| `generous` | +2% / +4% | `topProb ≥ 25%` 或 `offerRatio < 0.35` 或接受模型 `p < 0.30` | 每 3 轮最多 1 次 | “我佩服你的胆量，给你一个体面的数。” |
| `finalPush` | +2% | `round = 9` | 每局 1 次 | “最后报价，落袋为安。” |

- 档位选择：`lowball` 按怒气档 33/66/100 取 2/3/4；`rebate` 按 `rejectStreak` 取 2/3/4；`generous` 按 `topProb` 或 `p` 取 2/4。
- 所有档位在 `config/banker.ts` 中配置，不硬编码。
- `finalPush` 的 +2% 与 `rebate` 不叠加；第 9 轮优先 `finalPush`。
- 若第 9 轮前已提前结算（R-5.2.7），计划系统直接结束，不补报价。

### 5.2 选择算法（P0 启发式）

先按条件过滤候选，再按权重抽样；**拒绝后不一定补偿**，保证不可预测性。

```text
ctx = buildContext(...)
if (ctx.round == 9) return finalPush()

candidates = plans.filter(allowed(ctx))     // steady 永远可选
weights = weightTable(ctx)                  // 见下表
return pickWeighted(candidates, weights, bankerRandom)
```

| 局面 | steady | lowball | rebate | generous |
| :--- | ---: | ---: | ---: | ---: |
| 常规（无特殊触发） | 4 | 1 | 0 | 1 |
| 上轮被拒（`round ≤ 8`） | 2 | 1 | 3 | 1 |
| 顶奖概率 ≥25% | 2 | 0 | 1（若被拒） | 3 |
| 怒气 ≥66 且顶奖概率 ≤10% | 1 | 3 | 1（若被拒） | 0 |
| 第 9 轮 | — | — | — | —（强制 `finalPush`） |

- 权重是“倾向”，不是保证：上轮被拒时 rebate 权重 3 > lowball 1，但仍有 1/5 概率压价；连续拒绝且顶奖概率低时 lowball 升到 3，形成“他急了，可能哄你也可能压你”。
- 每个计划仍受次数/冷却限制；第 9 轮 `finalPush` 强制；`rebate` 与 `lowball` 同轮互斥（权重抽样时先排除）。
- 权重表放 `config/banker.ts`，可按角色/模式覆盖；调参不改代码。
- 计划历史写入快照 `bankerPlanHistory`（最近 3 条），供防重复与 UI 展示。
- 确定性：给定 seed 与快照，权重抽样可复现；回放/测试一致。

### 5.3 为什么这样设计

- **压价**不是随机欺负人，而是“你连续拒绝 + 顶奖概率低”时的合理施压；玩家能从怒气条与计划标签预判。
- **补偿**让“拒绝”不总是纯负收益：怒气 −6%、补偿 +4%，净 −2%，玩家仍有“再赌一把”的理由；但补偿不是必然，拒绝也可能换来更狠的压价。
- **慷慨**在顶奖概率高或玩家明显要跑时出现，制造“他怕了”的高光；上限 +4%，不会把 EV 送穿。
- **最后报价**给终局一个明确的戏剧节点，避免第 9 轮仍是普通报价。

## 6. 接受概率模型（银行家内部）

P0 可以用简单规则；P1 用可解释的线性模型估计玩家接受概率，仅用于选计划，不展示给玩家。

```text
ratio = offer / max(ev, 1)
risk  = stdev(remaining) / max(ev, 1)
z = −2.4
    + 5.2 × ratio
    − 0.8 × risk
    + 0.35 × (round / 9)
    + personaBias
    − 0.2 × (rage / 100)

p = 1 / (1 + exp(−z))          // clamp [0.02, 0.98]
```

| 角色 | `personaBias` |
| :--- | :--- |
| 稳重 | +0.15 |
| 赌徒 | −0.35（不能操作 Deal；No Deal 改为继续；模型主要用于台词/计划选择） |
| 从众 | +0.05，另加 `(avgMood − 3) × 0.05` |

- 计划评估时，用“假设报价”重算 `ratio` 与 `p`；目标把 `p` 拉回 **0.40–0.65**。
- 只用于选择计划，不参与报价钳制；即使模型失真，报价仍受 §3 管线约束。
- 参数放 `config/banker.ts`，上线后可用真实接受率校准；不要在前端展示 `p`（调试面板除外）。
- 校准指标：Brier score、各角色接受率、计划分布；模拟脚本先跑，真实数据后补。

## 7. AI 接入设计（P2）

### 7.1 接口边界

```ts
export interface BankerBrain {
  plan(ctx: BankerContext): BankerPlan | Promise<BankerPlan>
}

export interface BankerPlan {
  plan: 'steady' | 'lowball' | 'rebate' | 'generous' | 'finalPush'
  delta: number          // 必须在计划允许的档位内
  lineKey: MessageKey    // 只能从允许的台词池选
  reason: string         // ≤120 字，仅审计，不展示
}
```

- `HeuristicBrain`：P0 同步实现，永远可用。
- `RemoteBrain`：P2，调用后端 `/api/v1/banker/plan`；**只返回计划与台词 key**，不返回金额。
- `GameEngine` 只依赖 `BankerBrain`；切换实现不改规则代码。
- 客户端仍用确定性管线计算报价；服务端返回值即使被篡改，也只能在计划上限内生效（服务端另做一次校验）。

### 7.2 LLM 调用约束

| 项 | 约束 |
| :--- | :--- |
| 输入 | 数值化 `BankerContext` + 允许计划表 + 3 条风格示例；**不含玩家箱金额/未开金额** |
| 输出 | JSON：`plan`、`delta`、`lineKey`、`reason`；≤200 tokens |
| 模型 | 任意支持 JSON/结构化输出的模型；provider 可替换 |
| 超时 | 800ms；超过则用启发式，不等待 |
| 失败 | 网络错误/非法 JSON/越界 → 回退启发式，记录 fallback |
| 频率 | 每轮最多 1 次；同一 `contextHash` 缓存 10 分钟 |
| 成本 | 每日预算 + 每局上限（9 次）；超限自动降级 |
| 安全 | API key 只在服务端；限流/鉴权；不接收自由文本；无 PII |
| 审计 | 记录 prompt 版本、模型、token、延迟、计划、fallback、会话 id；保留 90 天 |

**关键**：LLM 负责“选哪个计划、说哪句”，数值由 `delta` 档位 + 确定性管线决定。这样既保留 AI 的“性格”，又不会出现“AI 乱报价”“AI 读箱”的问题。

### 7.3 延迟隐藏

- 报价前有 **0.9s 揭示停留 + 银行家“思考”动画**；在 `closeRound()` 后立即发起请求，通常能在面板出现前返回。
- 若 800ms 未返回：先用启发式出价，**不二次替换**（避免数字跳动）；`reason` 标记 fallback。
- 可选 P2：开局预取“9 轮计划骨架”，每轮只做局部修正；适合低延迟但状态变化大的场景不采用默认。
- 网络不可用：游戏完全离线可玩（启发式），不阻塞。

### 7.4 服务端校验（必须）

- `plan` 枚举、`delta` 档位、`lineKey` 白名单、`reason` 长度；
- 再跑一遍上限校验（计划 ≤±4%、总压价 ≤10%、`m_eff ∈ [0,1]`）；
- 非法响应 → 400 + fallback 标志，客户端静默降级；
- 不把 LLM 原始输出直接写日志（可能含提示注入内容），只存结构化字段与 hash。

## 8. UI / 体验

### 8.1 银行家卡

- 新增计划徽章：`压价 −3%` / `补偿 +2%` / `慷慨 +4%` / `最后报价`；颜色区分（压价橙、补偿绿、最后金）。
- 徽章 tooltip：一句自然语言解释 + 数值来源；屏幕阅读器 `aria-label` 同步。
- 台词与计划绑定：每个计划 2–3 条台词，避免连续重复；语气与表情（smug/annoyed/angry/furious）联动。
- “思考”动画 300–500ms（不阻塞按钮），随后出报价；`prefers-reduced-motion` 下直接出。

### 8.2 报价面板

- 现有“恐惧/怒气”明细扩展为：
  ```text
  基础 48% · 恐惧 +2.1% · 怒气 −4.5% · 计划 −3% · 角色 −? · 观众 +?
  ```
  只显示非零项；移动端折叠为“明细”按钮，不挤压 Deal/No Deal。
- 计划徽章与明细一致；禁止只在台词里暗示、数值里暗改。

### 8.3 历史与回放

- `RoundHistory` 每轮增加计划标签（可选）。
- 快照保留 `bankerPlanHistory` 最近 3 条；结算面板可显示“本局银行家使用过的计划”统计（P1）。

## 10. 测试

| 文件 | 用例 |
| :--- | :--- |
| `OfferCalculator.spec.ts` | 管线公式；各来源上限；`breakdown` 求和 = `m_eff`；R-6.3 边界不破；RMS 模式不回归 |
| `BankerBrain.spec.ts` | 触发条件逐条；rebate 只在拒绝后；lowball 总压价 ≤10%；计划不连续 3 次；第 9 轮 finalPush；同 seed 可复现 |
| `AcceptanceModel.spec.ts` | `ratio` 单调；risk 单调递减；角色 bias；输出 clamp；极端值不 NaN |
| `RemoteBrain.spec.ts` | 超时 800ms 回退；非法 JSON/越界 delta 拒绝；缓存命中；fallback 标记 |
| `GameView.spec.ts` | 计划徽章、明细、Deal 可用性、无障碍标签；AI 失败不阻塞出价 |
| 模拟 | 10k 局计划分布/接受率/平均到手；检查 lowball 是否导致 Deal 率过低 |

验收：

1. 同一 seed + 同一操作序列 → 计划、报价、台词完全一致。
2. 任意报价满足 `lower ≤ offer ≤ anchor`（R-6.3.6），`m_eff ∈ [0,1]`。
3. 无任何“台词说补偿、数值没加”或反之的情况（徽章/明细/实际金额三者一致）。
4. 断网时游戏可完整游玩，计划全部走启发式。

## 11. 分阶段

| 阶段 | 内容 | 估时 |
| :--- | :--- | :--- |
| P0 | 修正管线 + 计划表 + 启发式 + 徽章/明细 + 单测 | 4–5 天 |
| P1 | 接受模型 + 模拟调参 + 历史/回放 | 2–3 天 |
| P2 | 后端 AI 网关 + 审计/限流/回退 + A/B | 5–8 天（不含后端基建） |

后端与 LLM 的引入条件、技术选型见 `技术栈与后端评估.md`。**P0/P1 不需要后端**。

## 12. 风险与对策

| 风险 | 对策 |
| :--- | :--- |
| 计划过多，玩家觉得“被针对” | 所有计划有可见徽章与触发条件；总压价 ≤10%；提供“公平模式”开关（关闭计划，仅保留 v1.4） |

| 回放/复现困难 | 种子分流域 + 计划历史入快照；测试固定 seed |

## 14. 银行家档案与赌徒局的存在感（v1.4）

### 14.1 档案注册表

- 新增 `src/config/bankers/`：
  - `BankerProfile`：`id`、名称/特质 key、`planWeights`、`offerMode`（curve / highest）、`lineTone`（sharp / gentle）。
  - `default`：当前尖酸压价型，计划权重为基线。
  - `charity`：已启用轮换；高慷慨/拒绝补偿权重、温和台词、最高曲线档报价。
  - `conspirator`：开局后常驻“套话”按钮，每轮一次；点击显示“想知道哪个呢？”，选择未开非玩家箱后记录低语；首击只记录、次击开箱并移除；文字默认隐藏，悬停/聚焦显示，移出/失焦隐藏；记录跨轮保留至游戏结束；50% 真 / 50% 假；同一箱重复套话不重掷。
  - `collector`：顶奖在场最终报价 ×0.96，顶奖清空 ×1.08；`BankerCard` 显示当前状态。
  - `casino`：开箱阶段可押“下一箱不是顶奖”，赢 ×1.06 / 输 ×0.92，每局最多 2 次。
- 新增 `src/views/game/services/bankers/` 的 `BankerStrategy` 注册表：档案配置只保留展示/计划/曲线，特性通过 `getQuirk` / `getStatusKey` / `sideBet` 接入；引擎不再为单个银行家写分支。
- `BankerBrain.chooseBankerPlan(ctx, random, profile)` 按档案覆盖计划权重；报价管线与计划上限不变。后续新增银行家只加档案 + 策略，不改引擎主流程。
- 新局从打乱后的银行家队列取下一个；队列按 `default:charity:conspirator:collector:casino = 4:1:1:1:1` 生成，耗尽重洗，避免跨边界连续重复（`BankerRotation`）。
- 未来接入选择 UI 时，建议“银行家选择”与“随机模式展示”并列；`charity` 的 `offerMode: 'highest'` 走单独校准，不直接改默认曲线。

### 14.2 赌徒局里银行家为什么还重要

赌徒不能接受报价，Deal 隐藏，表面上看报价没有决策价值。当前用两类设计保留存在感：

1. **打脸记分牌（已实现）**：记录本局银行家最高报价；结算显示“银行家最高报价 vs 你的终局奖金”，给出“你打败了银行家 / 银行家笑到了最后”。赌徒终局超过最高报价时额外 +10% 荣誉奖励（`honorBonus`）。
2. **报价作为信息源（已实现）**：OfferPanel 已展示“报价/期望”，并保留信心、恐惧/怒气/计划明细；赌徒可把该比值当作银行家对剩余大奖的判断，辅助最后换箱决策。

### 14.3 可选的强化方案（按趣味优先排序）

| 方案 | 玩法 | 成本 | 风险 | 建议 |
| :--- | :--- | :--- | :--- | :--- |
| A 打脸奖励 | 终局奖金 > 最高报价 → 额外 +10% 荣誉奖金 | 低 | 改变数值平衡 | **已实现** |
| B 报价读心 | 显示“报价/期望”，并给换箱建议 | 低 | 信息过载 | **已实现（比值）**；换箱建议待补 |
| C 全押倍率 | 每拒绝一次报价，终局顶奖倍率 +0.1（上限 +0.9） | 中 | 与固定 ×2 冲突，需改规则 | 需拍板 |
| D 场外盘口 | 每轮银行家开一个“顶奖还在”的盘口，玩家用虚拟筹码下注 | 高 | 新系统/平衡复杂 | P2 |

**建议**：先保留 A 的“记分牌”叙事（已实现），P1 加 B 的“报价/期望”提示；C/D 等银行家角色系统上线后再评估。

### 14.4 赌徒终局与银行家台词

- 赌徒局每轮仍出报价、仍选计划、仍播台词；No Deal 不作为选项，只有「继续开箱」。
- 最高报价用于结算复盘；银行家台词可对“你一直不接价”做专门嘲讽（P1 台词池扩展）。
