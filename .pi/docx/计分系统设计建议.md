# 结算计分系统设计建议

**状态**：草案 v0.1 · **产品决定暂不落地**（存档，未实现）
**决策**：当前先继续玩法稳定与 P1 内容，计分系统暂缓，不进入开发；本文档仅作未来方案存档。

**目标**：把“角色强度平衡”从到手金额转移到结算分数；让不同角色有相近的长期平均强度，同时保留高风险高波动、低风险低波动。
**前提**：到手金额、报价、Deal/No Deal 规则不变；分数只作为结算与纪录，不反向影响局内奖金。

---

## 1. 先定原则

### 1.1 分数不是金额

如果直接按金额排名，巨奖模式的 $5M 会天然压过经典的 $1M，强角色也会天然压过弱角色。分数必须做**归一化**：

- 按模式归一化：经典 / 巨奖不能直接比绝对值；
- 按 k 归一化：经典 k=2 与 k=6 的期望差距很大；
- 按角色归一化：角色强度不应由“谁的基础期望高”决定；
- 按参考策略归一化：避免玩家用了不同策略就被系统判定为“更强”。

### 1.2 分数分成“结果 + 技能 + 最高奖”

建议总分上限 **1000**，拆成三块：

| 组成 | 建议上限 | 说明 |
| :--- | ---: | :--- |
| 结果分 | 550 | 最终到手相对“该角色/模式/k 的基准” |
| 技能分 | 300 | 使用角色能力、做对关键决策的加分 |
| 最高奖分 | 150 | 最终拿到最高奖额外奖励 |
| **总分** | **1000** | 三项相加后截断，避免无限膨胀 |

这样最高奖有存在感，但不会单靠运气把分数打穿；技能分也不会完全覆盖结果。

---

## 2. 推荐算法 v0

### 2.1 结果分

```text
outcome = 550 × clamp(prize / baseline(mode, k, persona), 0, 1.25)
```

- `prize`：最终到手金额（分）；
- `baseline(mode, k, persona)`：该模式、该 k、该角色在**参考策略**下的期望或中位数到手；
- 上限 1.25：超过基准 25% 后收益递减，防止极端高额把总分拉爆；
- `clamp` 下限 0：未拿到钱也有 0 结果分，不出现负分。

**为什么用角色基准**：强角色 baseline 更高，拿同样的钱得到的 outcome 更低；弱角色 baseline 更低，拿到同样的钱得到更高 outcome。这样可以把“角色基础强度”从分数里剥离出来。

**建议用中位数而不是均值**：少数顶奖会把均值拉高，中位数更稳定。若希望奖励极端高额，可改用均值并把上限设 1.5。

### 2.2 技能分

```text
skill = min(300, Σ 角色技能事件分)
```

技能分不是“技能造成的金额差”直接换算，而是**事件分**：每次有效使用技能给固定/封顶分，避免高额局一次技能就滚出巨大分数。

示例（数值只是起点，需模拟校准）：

| 角色 | 技能事件 | 建议分 |
| :--- | :--- | ---: |
| 稳重 | 没有贪心拒绝导致下一轮惩罚 / 在建议区间收手 | 40 |
| 赌徒 | 终局顶奖 ×2 | 100 |
| 赌徒 | 打脸银行家荣誉奖励 | 50 |
| 从众 | 观众推荐的箱开出低额 | 15/次，封顶 60 |
| 捡漏王 | 补出新顶奖 | 80 |
| 关系户 | 每次报价加成带来的有效增益 | 按百分比折算，封顶 80 |
| 保险员 | 终局非顶奖获得 50% 保底 | 60 |
| 主持人 | 使用造势/圆场 | 30；若随后成交额外 20 |
| 钉子户 | 每层骨气 | 20，封顶 60 |
| 欧皇 | 经典 13 个 $1M 开局 | 30（或只靠 baseline） |
| 无赖 | 直接截胡 | 120 |
| 唠叨 | 自动开箱造成高额损失 | 不建议给正向分；见 §3.3 |
| 阴谋家 | 主动套话并据此开箱 | 10/次，封顶 60 |
| 管理员 | 测试角色 | 不参与计分或单独标记 |

> 技能分应当**一次性触发**：同一能力同一局不能反复刷分；拖延、重复问同一箱等操作不应产生新分。

### 2.3 最高奖分

```text
jackpot = (prize === modeTopPrize) ? 150 : 0
```

- 无赖截胡按顶奖结算，也拿这 150；
- 巨奖模式拿 $5M 与经典拿 $1M 都算“本模式顶奖”，但结果分已被 baseline 归一化，不会因为 $5M 天然多几倍。

### 2.4 最终分

```text
raw = outcome + skill + jackpot
score = min(1000, round(raw))
```

建议结果面板展示三段拆分：

```text
本局得分 842
结果 512 · 技能 180 · 最高奖 150
```

这样玩家能理解“为什么是这个分”，而不是看到一个黑箱数字。

## 3. 角色强度怎么拉平

### 3.1 不是把每个角色的期望金额调成一样

高风角色应该允许：

- 更低的保底；
- 更高的上限；
- 更宽的分布；
- 同样的**长期平均分**。

建议给每个角色定义：

```text
目标平均分：600
目标标准差：
  低风险：70–90
  中风险：100–130
  高风险：150–190
```

例如：

- 保险员、关系户、稳重：分数集中，靠稳定结果 + 小技能分；
- 赌徒、无赖、欧皇：偶尔 850–1000，也经常 350–500；
- 唠叨：如果持续负收益，长期平均分会偏低，需要给“抗诅咒分”或降低其基准，不能只靠结果分。

**平均强度**指长期期望，不是每局都接近 600。

### 3.2 角色基准从哪里来

建议离线跑：

1. 固定一套参考策略（例如：报价/期望 ≥ 60% 时 Deal，否则 No Deal）；
2. 每个角色 × 模式 × k 跑 10,000 局；
3. 统计 **中位数到手** 作为 baseline；
4. 统计比分分布，调整技能分权重，使平均分接近 600、方差落在目标区间；
5. 分数参数写入配置，版本化，不在运行时动态改。

不建议在运行时按“本局角色”动态缩放最终分：玩家会觉得分数不可解释。

### 3.3 负面角色怎么办

唠叨的问题是：技能触发本身通常带来坏结果，如果只按“用了技能”给分，会奖励错误行为。

建议二选一：

- **A. 基线补偿**：唠叨 baseline 取它自己的较低期望；拿到同样的钱，outcome 更高，等于用分数补偿负面技能。
- **B. 反向成就**：给“触发诅咒但最终仍拿到 ≥ 某分数”的生存分，封顶 60。

我更推荐 A：分数逻辑更简单，也不会鼓励玩家故意触发坏事件。

---

## 4. 高风险高回报怎么落到公式

高风险角色的分数曲线建议：

```text
高风险：
  outcome 上限略低（如 1.15）
  skill/jackpot 上限略高
  分布尾部更厚

低风险：
  outcome 上限正常
  skill 更稳定
  分布更窄
```

不要给高风险角色同时更高的平均结果和更高的上限，否则会变成“必选”。

---

## 5. 需要避免的漏洞

1. **重复触发刷分**：同一技能每局只计一次，或每事件有独立上限。
2. **故意拖延**：分数不能与回合数、开箱数正相关，除非有明确成就。
3. **重复问同一箱**：阴谋家已锁定首次结果，不能靠重复套话拿技能分。
4. **技能分与结果分重复计算**：技能分只给“使用/决策”分，不能把技能带来的金额再加一遍。
5. **模式绝对金额**：不能直接按 prize 排名，必须按 baseline 归一化。
6. **管理员污染纪录**：管理员成绩建议单独标记，不进正式角色平均分。
7. **分数上限导致同分**：上限 1000 可以让极端局并列，但要保留拆项；如果希望区分，可把上限提到 1200 或增加“同分时比结果分”。

---

## 6. 我建议的落地顺序

1. **先做 v0 计分，不改任何角色数值**：观察每个角色 10,000 局的平均分和分布；
2. **只调 baseline 与技能权重**，把平均分拉近 600；
3. **再做角色技能比率调整**：高风险角色提高上限、降低保底；低风险角色降低波动；
4. **最后才考虑**每日挑战、排行榜、赛季分。

不要在计分系统还没校准前先大改角色金额，否则无法判断是分数算法还是角色数值造成的变化。

## 8. 结论（建议）

**建议先采用 v0：550 结果分 + 300 技能分 + 150 最高奖分，总分上限 1000；按模式、k、角色做 baseline 归一化；离线模拟校准到平均约 600 分，再通过方差区分高低风险角色。**

这是可解释、可测试、可迭代的起点；在分数系统验证前，不建议继续用“提高/降低角色金额”直接做平衡。
