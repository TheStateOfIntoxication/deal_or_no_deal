# 玩法卡牌与角色设计（v1.4 · 已实现 P0）

**状态**：P0 已落地（纯前端，玩法卡 / 巨奖模式 / 8 角色 / 观众 / 启发式银行家 / 5 银行家档案）；规则已回写 `需求文档.md` v1.8 §14。多卡叠加（未来角色被动）仅预留接口，未启用。
**范围**：优化点 1（开局玩法卡牌）、优化点 3（观众角色）、优化点 4（玩家角色）。
**依据**：`需求文档.md` v1.8（§14）；`银行家AI设计.md`；`技术栈与后端评估.md`。
**设计原则**：趣味优先；规则先于表现；随机可复现（种子分流域）；不引入后端；所有影响报价的修正必须可见。

---

## 1. 目标与结论

| 优化点 | 要解决的问题 | 本设计给出的答案 |
| :--- | :--- | :--- |
| 1 玩法卡牌 | 每局开局完全相同，重玩性低 | min(3, 模式数) 张背面玩法卡（当前 2 张），抽 1 张翻面确认；模式由注册表驱动，新增玩法只加配置与卡面 |
| 3 观众角色 | 只有玩家与银行家，场面冷清 | 3–5 名随机观众，每轮推荐箱号；开出小额欢呼、开出大额愧疚；情绪只影响台词，默认不改规则 |
| 4 玩家角色 | 玩家没有身份与取舍 | 6 张正面角色卡：稳重 / 赌徒 / 从众 / 捡漏王 / 关系户 / 保险员，各自一条**绑定规则** + 一条**建议策略** |

**结论**：三项均可纯前端实现；新增模式、角色、观众都是**数据 + 纯函数服务**，不需要后端。银行家计划见 `银行家AI设计.md`。

## 2. 统一开局流程

### 2.1 流程

```text
启动
  → 抽玩法卡：N 张背面 → 选 1 张 → 3D 翻面 → 读规则 → 确认
  → 选玩家角色：3 张正面角色卡 → 选 1 张 → 确认
  → 模式准备：
       经典模式：金球摇奖决定 k（2–6 个 $1M）
       巨奖模式：巨奖揭幕（固定 1 个 $5M，无摇奖）
  → 主流程（选箱 → 9 轮开箱报价 → 终局交换/结算）
```

### 2.2 状态机

在 `useGameSession` 外层增加 `SetupPhaseEnum`，原 `drawing: boolean` 由 `setupPhase` 取代（保留 `drawing` 计算属性做兼容，`drawing = setupPhase === modeSetup && mode.setup === 'k-draw'`）。

| 阶段 | 界面 | 可执行操作 | 进入条件 |
| :--- | :--- | :--- | :--- |
| `modeDraw` | 背面玩法卡 ×min(3, 模式数) | 点选一张 | 启动 / 再来一局 |
| `modeReveal` | 选中卡翻面 + 规则摘要 | 确认 / 返回重选（仅未确认时） | 选卡 |
| `personaPick` | 角色卡 ×3 | 选一张 → 确认 | 玩法确认 |
| `modeSetup` | 经典：`DrawPanel`；巨奖：`JackpotIntro` | 摇奖 / 开始 | 角色确认 |
| `playing` | 现有游戏页 | 现有操作 | 开局成功 |

- **顺序理由**：先定玩法再定角色，玩家能根据“本局有没有 $5M”选择赌徒或稳重；角色卡不随机，避免双重随机造成挫败。
- **重选**：玩法卡翻面后、确认前允许改选另一张（仍只翻一张，不改牌堆）；确认后不可退回。角色确认后不可改。
- **再来一局**：回到 `modeDraw`，重新洗牌、重新抽角色；不自动沿用上一局（与现有“结算不自动开新局”一致）。
- **可选（P1）**：“沿用上局玩法+角色”快捷入口，减少重复点击；默认关闭。

### 2.3 随机种子分流域（必须）

现有引擎用一个 `RandomSource` 驱动 k、洗池、报价扰动。新增玩法卡、观众、银行家计划后，**绝不能共用同一条随机流**，否则新增功能会改变原有牌局（回放/测试全乱）。做法：

```ts
// src/utils/random.ts
export function createSeed(): number            // crypto.getRandomValues 优先，回退 Date.now()^Math.random()
export function deriveSeed(seed: number, salt: string): number  // FNV-1a 32 位
```

| 随机流 | 种子 | 用途 |
| :--- | :--- | :--- |
| `deck` | `deriveSeed(sessionSeed, 'deck')` | 玩法卡顺序、角色卡顺序（若需要） |
| `engine` | `deriveSeed(sessionSeed, 'engine')` | k、洗池、报价扰动（现状不变） |
| `audience` | `deriveSeed(sessionSeed, 'audience')` | 观众人数、成员、推荐箱号、台词选择 |
| `banker` | `deriveSeed(sessionSeed, 'banker')` | 银行家计划选择、台词选择 |

- `sessionSeed` 写入本局记录，便于复现与排障。
- 测试一律显式传 seed；UI 层不允许直接 `Math.random()` 决定规则相关结果。

## 3. 玩法卡牌系统

### 3.1 数据模型

```ts
// src/config/modes/types.ts
export type GameModeId = 'classic' | 'jackpot'   // 后续追加
export type ModeSetupKind = 'k-draw' | 'fixed'

export interface GameModeDefinition {
  id: GameModeId
  nameKey: MessageKey
  taglineKey: MessageKey
  descKey: MessageKey
  ruleKeys: MessageKey[]          // 卡面 3 条规则
  icon: string                    // emoji / 内联 SVG id，不引外部图
  tone: 'gold' | 'violet'         // 卡面配色
  setup: ModeSetupKind
  /** 直接映射为 GameConfig 覆盖项；金额全部为分 */
  config: {
    baseAmounts: number[]         // 25 项，不含顶奖
    topPrize: number
    randomKEnabled: boolean
    fixedK: number                // 经典默认 2；巨奖固定 1
    kMin: number
    kMax: number
    kWeights: number[] | null
    offerBaseMode: 'mean' | 'rms'
  }
  /** 角色/观众/银行家计划是否在本模式启用；默认全开 */
  features?: Partial<{ persona: boolean; audience: boolean; bankerPlans: boolean }>
}
```

注册表 `src/config/modes/index.ts` 导出 `MODES: GameModeDefinition[]`、`MODE_MAP`。新增玩法 = 新增一个对象 + 4–6 个 i18n key + 一张卡面样式，不改引擎。

### 3.2 牌堆与抽取

```ts
// src/views/game/services/ModeDeckBuilder.ts
export interface ModeCard { modeId: GameModeId; revealed: boolean }
buildModeDeck(modes, count = 3, random): ModeCard[]  // 不放回抽取
```

- 牌数 = `min(3, 注册模式数)`；当前 2 种模式 → **2 张卡**（不做“未来玩法占位卡”，避免空卡）。
- 同一牌堆不出现重复模式；顺序由 `deck` 流洗乱。
- 卡背完全一致，只有选中后才 `revealed = true`；DOM 中不提前渲染正面文案（只渲染卡背；翻面后才挂载正面），减少“看源码作弊”的收益（§9.7 已接受单机可被查看，这里只做低成本防剧透）。
- 选中后其余卡置灰不可点；确认按钮出现。翻面动画 0.5s，`prefers-reduced-motion` 下直接显示正面。
- **当前只启用单卡**：`selectedModeIds` 先按 1 张实现；牌堆与 `GameModeDefinition` 已支持多张候选。多卡叠加需要先定义“金额池如何合并（26 箱不变？顶奖如何叠加？）”，暂留给未来角色的被动技，避免先做出错误规则。

### 3.3 模式 A：经典（现状迁移）

| 项 | 值 |
| :--- | :--- |
| 顶奖 | $1,000,000 × k（k 由金球摇奖决定） |
| k | 2–6，均匀（可配权重） |
| 金额池 | 25 项基础表移除最低 (k−1) 项 + k 个顶奖 = 26 箱 |
| 最低金额 | k=2 → $1；k=6 → $50 |
| 期望值 | $169,939（k=2）～ $323,784（k=6），k 均匀时约 $246,862 |
| 准备步骤 | 现有 `DrawPanel` 金球摇奖 |

规则不变（R-4.1、R-4.2、R-6），只是从“唯一开局”变成“卡牌之一”。

### 3.4 模式 B：巨奖（500 万唯一）

| 项 | 值 |
| :--- | :--- |
| 顶奖 | **$5,000,000 × 1**（全场唯一） |
| 其他金额 | 基础表 25 项原样保留：$0.01、$1 … $750,000；**本模式没有 $1M** |
| 金额池 | 25 + 1 = 26 箱 |
| 最低金额 | $0.01 |
| 期望值 | `(2,418,416.01 + 5,000,000) / 26 = $285,323.69` |
| 单箱中 5M 概率 | 3.85% |
| 5M 占期望值比例 | 67.4% |
| 准备步骤 | 无摇奖；`JackpotIntro` 揭示“唯一 $5M 已封入”，点开始 |
| 锚点 | 默认均值 `mean`；**不启用 RMS**（5M 会把 RMS 拉到约 $98 万，现有 RMS 曲线未校准，见 §3.6） |

**规则可行性**：现有 `PoolBuilder.build(config, k)` 对 `k = 1` 天然成立——移除最低 0 项，追加 1 个顶奖。只需让固定模式允许 `fixedK = 1`，并跳过 R-4.1.2 的 2–13 校验（巨奖模式新增规则 R-4.2.8：顶奖数固定为 1，不受 k 范围约束）。这是本设计里引擎改动最小的部分。

**张力设计**：

- 5M 被开走时，剩余期望值从 $285,324 跌到 `2,418,416.01 / 25 = $96,736.64`（−66%），报价会立刻塌陷；这是本模式的核心戏剧点。
- 5M 存活时，报价按高期望值走，玩家会更想“再开一个”；但单箱概率只有 3.85%，一旦失去就没有第二张底牌。
- 银行家恐惧：p=3.85% 低于 10% 枢轴，前期恐惧加价为 0；终局两箱时 p=50%，恐惧也只有 +4%（现有公式上限 8% 基本吃不满）。**结论**：巨奖模式是“高期望、低恐惧”，与经典的“多顶奖、恐惧明显”形成差异；不建议为此改全局恐惧参数。
- 若试玩觉得过于温和，P1 可加 `mode.fearPivot = 0.04` 的**模式级覆盖**（需需求文档修订并在界面明示），不改 R-6.4 默认值。

**建议验收数字**：5M 唯一、1M 不存在、26 箱、最低 $0.01、期望 $285,324±1、每局 `topPrizeRemaining` 初始为 1、开走 5M 后为 0。

### 3.5 卡面内容（文案骨架）

| 卡面 | 经典 | 巨奖 |
| :--- | :--- | :--- |
| 标题 | 百万金球 | 唯一天价 |
| 一句话 | 摇出你的百万箱数量 | 全场只有一个 500 万 |
| 规则 1 | 金球摇奖决定 2–6 个 $1M | 唯一一个 $5M，没有 $1M |
| 规则 2 | 26 箱，最低 $1–$50 | 26 箱，最低 $0.01，次高 $750K |
| 规则 3 | 开满 9 轮，银行家报价 | 开满 9 轮，银行家报价 |
| 数据 | 期望 $170K–$324K | 期望 $285K · 中奖 3.85% |
| 难度标签 | 标准 | 高风险高期望 |

### 3.6 扩展新玩法（接口约定）

新增玩法只允许通过以下扩展点，不得在 `GameEngine` 里写 `if (modeId === ...)`：

1. `MODES` 注册新对象（金额、k 规则、准备步骤、feature 开关）。
2. 新增准备组件（若 `setup` 不是 `k-draw`/`fixed` 之一，在 `SetupScene` 注册映射）。
3. 如需影响报价：在模式配置里给 `offerBaseMode`、乘数曲线覆盖，或使用 `ModeRule` 钩子（P1）：
   ```ts
   interface ModeRule {
     id: string
     onBeforeOffer?(ctx: OfferContext): { delta: number } | void
     onAfterOpen?(ctx: OpenContext): void
     onSettle?(result: GameResultState): GameResultState
   }
   ```
   钩子必须是纯函数、有上限、在界面明示；禁止远程调用。
4. 新增 i18n key（中英同步、字母序），跑 `npm run tsc` 与模式单测。

**明确不做**：模式内再随机金额表（R-10.1 未实现）、模式内改开箱序列（R-5.1.3）、模式内改箱数（R-4.2.7 未实现）。

## 4. 观众系统

### 4.1 成员生成

```ts
interface AudienceMember {
  id: string
  nameKey: MessageKey
  emoji: string            // 头像，不引外部图片
  trait: 'hype' | 'cautious' | 'gambler' | 'superstitious'
  mood: number             // 0–5，初始 3
}
```

- 人数：基础 3–5 人（`audience` 流随机）；**从众**角色 +1（4–6 人）。
- 成员模板 8 个，随机不重复取 N 个；名字走 i18n（`AudienceName1..8`），不出现真实人名。
- 每局固定，不中途换人；情绪局内累计，新局重置。

### 4.2 推荐机制

- 时机：进入每轮 `opening` 阶段（首次选箱后、每次 No Deal 后）时，随机 1 名成员推荐 1 个**未开启的非玩家箱**；从众角色推荐 2 个（不同成员、不同箱，若可选）。
- 选择方式：在合法箱号集合中**均匀随机**，**只使用箱号与种子，绝不读取箱内金额**。这是硬约束：推荐不得泄露任何未开金额信息。
- 展示：成员头顶气泡「开 17 号！」+ `CaseGrid` 对应箱金环 + “观众推荐”角标；本轮结束（开完配额/出报价）后气泡淡出。
- 边界：剩余可选箱 ≤1 时不推荐；提前结算/终局时清空气泡；观众推荐不影响开箱配额与合法操作。

### 4.3 反应规则

以开出的金额在原金额池中的累计分位 `share = count(pool ≤ amount) / poolSize` 判定（池不变，分位稳定）：

| 条件 | 情绪 | 表现 | 文案示例 |
| :--- | :--- | :--- | :--- |
| `share ≤ 0.30`（当前盘面小额） | +1（上限 5） | 起立欢呼、金色纸屑微动效 | “好耶！送走一个小数目！” |
| `share ≥ 0.90`（当前盘面大额） | −1（下限 0） | 捂脸、低头、灰暗 | “对不起……我不该乱喊的。” |
| 其他 | 不变 | 点头/耸肩 | “还行，继续。” |

- 仅当被开箱是**该成员推荐过的箱**时才反应；没听推荐不触发。
- 同一轮两名观众推荐同一箱时，两人都反应；不同箱则只有对应推荐者反应。
- 反应只挂在 `RevealChip` 的附加标签与成员气泡上，不新增阻塞动画；`prefers-reduced-motion` 下只换文案与表情。
- 分位阈值放 `config/presentation.ts`：`AUDIENCE_HAPPY_SHARE = 0.30`、`AUDIENCE_GUILT_SHARE = 0.90`；硬编码不得进入组件。

### 4.4 情绪与规则的关系（v1.5 边界）

- **默认纯表现**：情绪只影响台词、表情、气泡；不改变报价、概率、金额池。
- **唯一例外（从众角色）**：见 §5.3，平均情绪 ±1%/点，封顶 ±2%；这是角色规则，不是观众默认规则，且在报价明细中单独列项。
- 观众不会“知道”箱内金额；推荐是盲选。任何“提高推荐命中率”的设定都会泄露信息，禁止。

### 4.5 UI 与移动端

- `AudienceRow.vue` 放在 `CaseGrid` 下方，横向排列；桌面显示全部，移动端最多 4 个头像 + “+N”，可横向滑动。
- 每个头像：emoji + 名字 + 5 格情绪点（不只靠颜色，附数字/心形）。
- 气泡绝对定位在头像上方，2 行内截断；同屏最多 2 个气泡，避免遮挡箱子。
- 推荐环通过 `CaseGrid` 新增 prop `recommendedCaseNos: number[]` 渲染，不改变点击逻辑。

### 4.6 公平性与测试

- 单测：推荐箱必须未开启、非玩家箱、属于当前可选集合；用“金额全相同/金额差异极大”两组池跑同一 seed，推荐序列必须**完全一致**（证明未读金额）。
- 情绪只在推荐命中时变化，范围钳制 0–5；反应映射表逐档测试。
- UI 测试：3–5 个头像、推荐环、开箱后情绪变化、移动端不溢出。

## 5. 玩家角色系统

### 5.1 角色定义

| 角色 | 一句话 | 绑定规则 | 建议策略（非强制） | 补偿 | 难度 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **稳重**（老会计） | 见好就收 | 若报价 ≥ **80% EV** 仍拒绝，则下一轮报价额外 −3%（每次触发，局内最多 2 次） | 报价 ≥ **65% EV** 时提示“可以收手” | 无；新手默认 | ★ |
| **赌徒** | 不到最后不回头 | **没有回头路**：不能操作 Deal（隐藏）；No Deal 按钮改为「继续开箱」；终局交换保留。进入终局时：顶奖 → **×2**；非顶奖 → **10%**（均向下取整到分） | 永不建议收手 | 无固定加成；终局规则见左 | ★★★ |
| **从众** | 听大家的 | 观众推荐 **2 个**箱；观众平均情绪影响报价 **±1%/点，封顶 ±2%** | 平均情绪 ≥3.5 → “再开一个”；≤2.5 → “收手吧”；中间 → “再听听” | 无；中等 | ★★ |
| **捡漏王** | 把天补上 | 顶奖全部开出且仍有 ≥5 个未开箱时，将一个非玩家剩余最大金额补成新顶奖；每局一次 | 尽早开出顶奖以触发 | 无；中高 | ★★ |
| **关系户** | 把价抬起来 | 银行家每次报价额外 **+8%**（仍受上界钳制） | 报价高于常规，可更早收手 | 无；新手友好 | ★ |
| **保险员** | 最后一箱也值钱 | 终局最终箱非顶奖时，获得该箱金额的 **50%**；顶奖正常 | 终局非顶奖也有保底 | 无；中 | ★★ |
| **主持人** | 把场子控住 | 每局一次主动控场：造势（当前报价 ×1.05，怒气 +20，观众 +2）或圆场（当前报价 ×0.98，怒气 −25，观众 −1） | 想成交用造势，想续开用圆场 | 无；中低 | ★★ |
| **钉子户** | 越拒越硬 | 拒绝 <55% EV 的报价叠 1 层骨气（最多 3 层），每层后续报价乘数 +3% | 低报价可硬扛，高报价别贪 | 无；低 | ★ |

### 5.2 为什么这样定

- **稳重**：不强制玩家，只惩罚“明显贪心”（≥80% EV 还拒绝），让“稳”有身份感；80% 阈值只在第 8–9 轮常见，不会天天触发。
- **赌徒**：不能操作 Deal（隐藏）；No Deal 按钮改为「继续开箱」，玩家唯一能主动做的是点击继续。如果不 Deal（实际上无法 Deal）并撑到终局，顶奖 ×2、非顶奖只有 10%，形成“没有回头路，只能赌最后一箱”的高风险高回报。手动继续给了读价时间，也避免按钮死锁。
- **从众**：观众从“纯气氛”变成“可感知的倾向”，但影响封顶 ±2%，不会盖过银行家/怒气的主修正；推荐 2 个箱让“听劝”更有参与感。
- **捡漏王**：给“把顶奖开光”一个奖励，让玩家在早期主动追顶奖；限制非玩家箱与剩余 ≥5，避免最后两箱时白送顶奖，也避免泄露玩家箱。
- **关系户**：把“报价”变成角色收益，适合新手；+8% 是金额加成，不改变计划/怒气逻辑。
- **保险员**：给“终局差一点”一个 50% 保底，鼓励玩家不轻易 Deal；只作用于终局，不影响报价。
- **主持人**：把“观众情绪/银行家怒气”变成一次性筹码。造势是成交前的加价，圆场是继续前的降怒；两个方向都有代价，不能无脑点。
- **钉子户**：和稳重相反，奖励“对低报价说不”。层数绑定低报价，不会奖励无脑拒高价；+9% 上限避免压过关系户的常驻 +8%。

### 5.3 报价修正接入

统一修正管线（详见 `银行家AI设计.md` §3）：

```text
m_eff = clamp(base + fear − rage + plan + persona + audience, 0, 1)
final = floor(clamp((lower + (reference − lower) × m_eff) × (1 + raise), lower, upper))
```

银行家特性（收藏家/赌场老板）与主持人主动能力在 `final` 之后再乘比例，仍必须钳制到 `[lower, upper]`；对应 `OfferBreakdown.quirk` / `.action`，不与 `persona` 混用。

| 来源 | 角色 | 取值 | 触发 |
| :--- | :--- | :--- | :--- |
| `persona` | 稳重 | −0.03 | 上一轮报价 ≥80% EV 且 No Deal；下一轮生效一次 |
| `persona` | 赌徒 | 0 | —（终局规则在结算，不在报价） |
| `raise` | 关系户 | +8% 金额 | 最终报价 `raw × 1.08`，再走上界钳制 |
| `audience` | 从众 | `(avgMood − 3) × 0.01`，钳制 ±0.02 | 每轮报价时读取当前平均情绪 |
| `persona` | 钉子户 | `stacks × 0.03`，最多 +0.09 | 每次 No Deal 时若报价 <55% EV，叠 1 层 |
| `action` | 主持人 | 造势 +5% / 圆场 −2% | 报价阶段主动使用，每局一次；作用于当前报价 |
| `quirk` | 收藏家 | 顶奖在场 ×0.96；顶奖清空 ×1.08 | 按剩余顶奖数量自动切换 |
| `quirk` | 赌场老板 | 押中 ×1.06；押错 ×0.92 | 开箱阶段押“下一箱不是顶奖”，每局最多 2 次 |
| `audience` | 其他 | 0 | — |

- 顺序：先算 `base + fear − rage`，再加 `plan`、`persona`、`audience`，最后 `clamp[0,1]`；所有项写入 `offerMeta.breakdown`，`OfferPanel` 只展示非零项。
- 稳重惩罚与银行家 rebate 可同时存在（一个减、一个加），界面分别标注，禁止合并成“神秘调整”。
- 从众人数多 1 人时，平均情绪仍按 0–5 计算，避免人数放大系数。

### 5.4 结算与记录

`GameResultState` 扩展：

```ts
interface GameResultState {
  basePrize: number        // 箱内/报价原始金额
  personaBonus: number     // 终局修正（赌徒非顶奖为负数；其他角色 0）
  prize: number            // 最终到手 = basePrize + personaBonus
  // 现有字段不变
}
```

- 赌徒终局规则在 `settleByCase()` / `settleIfCertain()` 统一应用：顶奖 `floor(base × 2)`，非顶奖 `floor(base × 0.1)`；接受报价不触发。
- `payoutGrade` 按最终 `prize` 评级；结算面板显示基础奖金、角色修正（可为负）。
- `bestPrize` 与战绩用 `prize`（最终到手）；记录新增 `modeId`、`personaId`、`sessionSeed`。
- 提前结算（R-5.2.7）是系统强制，直接按赌徒终局规则结算；界面文案说明“命运提前揭晓，不算你反悔”。

### 5.5 建议提示（AdvisorHint）

- 位置：`OfferPanel` 上方一行，不遮挡 Deal/No Deal。
- 内容：角色头像 + 一句话 + 依据（如“报价为剩余期望的 72%”）。
- 稳重：`offer / EV ≥ 0.65` → 建议 Deal；否则“还能再看一轮”。
- 赌徒：始终显示“没有回头路；继续开箱到终局（非顶奖 10%，顶奖 ×2）”。
- 捡漏王 / 关系户 / 保险员：分别提示捡漏触发条件、+8% 报价、终局 50%。
- 从众：按平均情绪映射；建议文案直接引用观众喊出的箱号（如“观众在喊 7 号和 19 号”），不虚构“建议收手”的人数。
- 建议不是操作，不改变按钮可用性；赌徒只能点击「继续开箱」。

### 5.6 平衡目标

- 用模拟脚本（`scripts/simulate.ts`，node 运行，不进生产包）跑 10,000 局/模式/角色，策略集：
  1. 首个报价就 Deal；
  2. 报价 ≥60% EV 就 Deal；
  3. 报价 ≥80% EV 就 Deal；
  4. 永不 Deal。
- 指标：平均到手、Deal 率、5M/1M 命中率、低于 $100 的比例、各角色相对稳重的平均到手差。
- 目标：角色间平均到手差控制在 **±15%** 内；若赌徒显著高于稳重，降低顶奖倍率或提高非顶奖比例；若从众显著高，检查情绪修正是否过强。
- 平衡参数只放 `config/personas.ts`，不散落在组件。

### 5.7 第一档新增角色（已实现）

- **主持人**：`PersonaActionEnum.hostHype / hostCalm`；引擎只改当前报价与怒气，观众情绪增量返回给会话层 `AudienceDirector.adjustMood`。使用后 `personaActions` 清空，报价明细写 `action`。
- **钉子户**：`PersonaRuntimeState.stacks`；`onNoDeal` 判断报价/EV <0.55 后叠层，`getOfferDelta` 返回 `stacks × 0.03`；`personaState.stackBonus` 驱动界面提示。
- 两者都通过 `services/personas/` 的 `PersonaStrategy` 注册表接入，引擎不再新增角色 `if`。

## 11. v1.2 增量：新三角色与银行家档案

### 11.1 捡漏王

- 触发：本局 `topPrizeRemaining = 0`（唯一 $5M 或全部 $1M 已开）且未开箱数 ≥5（更强调“提前”）。
- 选择：未开启的**非玩家**箱中金额最大者；同额随机。
- 结果：该箱金额改为 `topPrize`，`topPrizeRemaining = 1`，每局一次；金额板、后续报价/信心立即更新，并显示触发提示。
- 不选玩家箱：避免“提示即泄露玩家箱”。

### 11.2 关系户

- 每次报价在 `OfferCalculator` 的原始金额上 ×1.08，再执行 R-6.3 上界钳制；`breakdown.raise = 0.08`，界面显示“角色加价 +8%”。
- 不改变计划、怒气、恐惧、观众与角色乘数。

### 11.3 保险员

- 终局（开箱/提前结算/交换后持有）最终箱非顶奖 → `floor(base × 0.5)`；顶奖正常；接受报价不触发。
- 结算显示基础奖金与负/正角色修正。

### 11.4 银行家档案（为后续扩展）

- `src/config/bankers/`：`BankerProfile` 注册表；
  - `default`：尖酸压价型；
  - `charity`：高慷慨/拒绝补偿权重、温和台词、最高曲线档报价；已启用轮换，不提供手动选择 UI。
- `BankerBrain.chooseBankerPlan` 接受 profile，计划权重按档案覆盖；报价管线保持不变。
- 阴谋家：每轮首次悬停未开非玩家箱时，35% 概率低语档位；60% 真 / 40% 假；每轮最多 1 次、每个箱最多 1 次，玩家箱不触发。
- 新局从打乱后的银行家队列取下一个；队列按 `default:charity:conspirator:collector:casino = 4:1:1:1:1` 生成，耗尽重洗，连开多局按序登场（`BankerRotation`）。
- 慈善家用最高曲线档（0.92）作为基础乘数，并使用温和台词池。

### 11.5 最高报价（银行家存在感）

赌徒不能接受报价，因此把报价变成“打脸记分牌”：

- 每局记录银行家最高报价；结算面板显示“银行家最高报价”，并与最终奖金比较，给出“你打败了银行家 / 银行家笑到了最后”。
- 不改变奖金，只提供叙事与复盘价值。
- **已实现**：赌徒终局奖金 > 最高报价时额外 +10% 荣誉奖励（`honorBonus`）；报价面板显示“报价/期望”。

### 11.6 银行家轮换

- 新局从 `GAME_BANKER_IDS` 的加权队列取下一个（default:charity:conspirator:collector:casino = 4:1:1:1:1）；队列耗尽后重洗，并避免跨队列边界连续重复。
- 当前档案：`default`（尖酸）、`charity`（慈善家）、`conspirator`（阴谋家）、`collector`（收藏家）、`casino`（赌场老板）；`BankerCard` 显示名称/特质/特性状态，台词按档案语气切换。
- 收藏家：顶奖在场 ×0.96，顶奖清空 ×1.08；赌场老板：开箱阶段押下一箱不是顶奖，赢 ×1.06 / 输 ×0.92，每局最多 2 次。
- 阴谋家：每轮首次悬停未开非玩家箱时，35% 概率低语档位；60% 真 / 40% 假；每轮/每箱最多 1 次。
- 轮换队列保存在当前页面会话内；刷新页面会重新洗牌。

### 11.7 打脸奖励与报价/期望

- 赌徒终局奖金 > 银行家最高报价时，额外 +10% 荣誉奖金，单独显示在结算面板。
- OfferPanel 增加“报价/期望”百分比；赌徒可据此判断银行家对剩余大奖的恐惧程度，辅助最终换箱。
- 换箱弹窗展示剩余两箱金额、顶奖状态、最后报价/期望、银行家信心，并如实说明“两箱各 50%，换箱不改变期望”。

## 12. 趣味性评估与扩展路线

### 12.1 当前趣味性判断

**强项**

- 核心循环仍是“选箱 → 开箱 → 银行家报价 → 风险决策”，短局、强反馈，适合重复游玩。
- v1.5–v1.8 增加了玩法卡、8 名角色、观众、银行家计划/轮换与 5 名银行家档案，单局差异明显变大。
- 赌徒“没有回头路”把单局变成一条不可逆的冒险曲线，适合直播/短视频切片；银行家最高报价与“打脸奖励”补上了叙事对手。
- 捡漏王/关系户/保险员分别对应“追顶奖 / 高报价 / 终局保底”，覆盖三种不同风险偏好。

**风险**

- 角色/模式/银行家组合变多后，平衡与解释成本上升；需要模拟与试玩数据。
- 赌徒局中报价不再影响成交，若只显示数字会显得“银行家没用”；目前用最高报价、报价/期望和打脸奖励补足，但仍偏叙事。
- 慈善家“最高曲线档”报价可能让普通局过于容易成交；需要限制登场频率或调整档位。
- 当前主要是单局乐趣，缺少长期目标（收集、解锁、每日挑战、排行榜）。

**主观评分（单机、无社交）**：当前约 **7.5/10**；完成平衡与银行家轮换后约 **8.5/10**；加入每日挑战/长期目标后可到 **9/10**。

### 12.2 扩展方向（按优先级）

| 优先级 | 方向 | 说明 | 依赖 |
| :--- | :--- | :--- | :--- |
| P0 | 银行家轮换完善 | 增加档案、登场概率、专属台词/出价风格；避免慈善家连续出现 | 无 |
| P0 | 报价读心/换箱建议 | 用“报价/期望 + 信心”给赌徒一个终局换箱提示 | 无 |
| P0 | 平衡模拟 | 8 角色 × 2 模式 × 5 银行家的策略模拟，校准捡漏/保险/关系户/主持人/钉子户 | 无 |
| P1 | 每日挑战 | 固定 seed + 固定模式/角色/银行家，结算分享 | 无（seed 即可） |
| P1 | 成就/图鉴 | 收集角色、银行家、触发被动、打脸次数；本地存档 | 无（后期可上云） |
| P1 | 更多观众互动 | 观众推荐连击、集体情绪、从众专属事件 | 无 |
| P2 | 多玩法卡叠加 | 未来角色的被动；需要先定义金额池合并规则 | 规则设计 |
| P2 | AI 银行家 | 只选计划/台词，不产出金额；需要后端 LLM 网关 | 后端 |
| P2 | 云存档/排行榜 | 需要后端 + 反作弊；建议先做本地最佳 | 后端 |
| P3 | 多人/观战 | 实时通道、房间、观战弹幕 | 后端/实时 |

### 12.3 推荐路线

1. **先做 P0 平衡与银行家轮换**：把 8 角色的平均到手、成交率、捡漏触发率跑出来；慈善家出现频率降一档。
2. **再做 P1 每日挑战 + 本地图鉴**：不引入后端，给长期目标。
3. **P2 才考虑 AI/云存档/排行榜**；AI 银行家必须先有网关与回退，不能阻塞游戏。
4. **多卡叠加**等未来角色被动设计确定后再做，避免先写死金额池合并规则。

### 12.4 首轮平衡模拟（200 局/组合）
