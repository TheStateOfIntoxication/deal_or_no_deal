# 技术栈与后端评估（v1.1 · 结论已执行）

**状态**：v1.5–v1.6 已按本评估执行：卡牌/观众/6 角色/启发式银行家与最高报价全部纯前端，**未引入后端**；战绩仍写 localStorage，AI 银行家（P2）待立项。
**范围**：优化点 1–4 是否需要后端（现有 JDK 25 + MySQL）、需要哪些技术栈、什么时候引入。
**依据**：`需求文档.md` v1.6、`玩法卡牌与角色设计.md`、`银行家AI设计.md`、当前前端代码。

---

## 1. 结论摘要

**当前四项优化都不需要后端。**

| 能力 | 需要后端？ | 现在怎么做 | 何时才需要 |
| :--- | :--- | :--- | :--- |
| 玩法卡牌 / 巨奖模式 | 否 | 前端注册表 + 纯函数牌堆 | 需要运营热更新玩法/灰度时（可先用静态 JSON） |
| 观众系统 | 否 | 前端种子随机 + 纯展示 | 不需要（除非做多人观战） |
| 玩家角色 | 否 | 前端配置 + 引擎修正 | 不需要（记录本地） |
| 银行家启发式计划 | 否 | 前端纯函数 + 种子 | 不需要 |
| **银行家 LLM** | **是（仅代理）** | 启发式兜底 | **唯一强触发**：要接 AI 时 |
| 云存档 / 跨设备 | 是 | localStorage | 用户要求换设备继续、清缓存不丢档 |
| 排行榜 / 反作弊 | 是 | 无 | 要做竞争榜、且不接受客户端作弊 |
| 远程配置 / 运营 | 可选 | 静态配置 | 需要热更新、A/B、每日挑战 |
| 数据分析 | 可选 | 无 / 轻量埋点 | 需要看模式/角色接受率、留存 |

**建议**：v1.5 保持纯前端；先做 P0（卡牌、巨奖、观众、角色、启发式银行家），用模拟脚本调平衡。后端只在“接 LLM”或“云存档/排行榜/远程配置”成为明确需求时再引入，且**只做薄服务**，不要把游戏引擎搬到服务端。

---

## 2. 现状

- 前端：Vue 3 + TypeScript + Vite + Vuex 4 + Element Plus（按需）+ SCSS。
- 规则：`src/views/game/services` 纯类/纯函数（`GameEngine`、`PoolBuilder`、`OfferCalculator`、`AmountGrader`），不依赖 Vue/DOM。
- 存档：`localStorage`（战绩、音效设置）。
- 部署：静态站点即可；无 API、无数据库、无登录。
- 测试：Vitest 3 个文件 36 用例；构建 `vue-tsc + vite build`。

这套结构对新增玩法/角色/观众很友好：新增配置 + 纯服务 + 组件即可，**没有引入后端的必要性**。

---

## 3. 逐项评估

### 3.1 玩法卡牌 / 巨奖模式

- 模式是**静态内容**：金额表、k 规则、卡面文案、准备步骤。
- 放前端 `src/config/modes/` 即可；新增模式发版即可。
- 需要“运营不发版加模式”时，才考虑远程配置（`GET /config` + 版本号 + 缓存）；第一版可用静态 JSON + 构建时注入。
- 不需要数据库。

### 3.2 观众系统

- 观众人数、成员、推荐箱号、反应全部是**本地随机 + 展示**。
- 推荐只读箱号，不读金额；没有跨玩家共享状态。
- 不需要后端；若未来做“多人观战/弹幕”，才需要实时通道（WebSocket/SSE），属于新需求。

### 3.3 玩家角色

- 三条绑定规则 + 建议提示，纯本地规则。
- 战绩按角色聚合即可放 localStorage；需要跨设备时并入云存档。
- 不需要后端。

### 3.4 银行家计划（启发式）

- 计划选择、接受概率、修正管线都是纯函数；种子可复现。
- 不需要后端；P0/P1 全部前端。

### 3.5 银行家 LLM（唯一强触发）

必须走后端代理，原因：

1. **密钥安全**：LLM API key 不能进前端包/浏览器。
2. **成本与限流**：按设备/会话限速、日预算、缓存，只能在服务端做。
3. **提示词与模型迭代**：不发版即可换 prompt/模型。
4. **审计与合规**：记录调用、延迟、token、计划、fallback；保留/删除策略。
5. **输出校验**：服务端二次校验计划/档位/台词白名单，避免 LLM 幻觉直接进游戏。

> 即使接 LLM，游戏引擎仍在客户端；服务端只返回“计划 + 台词 key + delta”，金额由客户端确定性管线计算。

### 3.6 云存档 / 排行榜 / 远程配置 / 分析

| 能力 | 触发条件 | 最小实现 |
| :--- | :--- | :--- |
| 云存档 | 用户明确要跨设备/防清缓存 | 匿名设备 id + `GET/PUT /records`，last-write-wins |
| 排行榜 | 要做“全网最高奖金”且能接受一定作弊 | 服务端存 seed + 操作日志，服务端重放校验；否则只做“本地最佳” |
| 远程配置 | 运营要热更新模式/参数/A-B | `GET /config` + ETag + 本地缓存 + 兜底默认值 |
| 分析 | 要看模式/角色/计划接受率 | 轻量事件上报（批量、采样、匿名）；或先用 Umami/Plausible |

## 4. 引入后端的触发条件（决策门槛）

按优先级：

1. **AI 银行家要上线**（P2）→ 必须有一个 LLM 代理服务。
2. **云存档/跨设备**成为用户诉求 → 记录服务。
3. **排行榜/竞技**立项 → 服务端校验；没有这个需求就不要做。
4. **运营要热更新/灰度/每日挑战** → 配置服务；可先用静态 JSON 过渡。
5. **需要看真实接受率/留存** → 分析服务；可先用轻量第三方。

不满足以上条件时，**不引入后端**：静态站 + localStorage 足够，运维成本最低，离线可玩。

## 5. 若引入后端：推荐架构

```text
浏览器（Vue3 静态站）
   │  HTTPS / JSON
   ▼
Nginx / CDN
   │
   ├── 静态资源
   └── /api/* → Spring Boot 服务（JDK 25）
                    ├── MySQL 8.4（记录/审计/配置）
                    ├── Redis（限流/缓存，可选）
                    └── LLM Provider（服务端持有 key）
```

### 5.1 技术选型

| 层 | 推荐 | 说明 |
| :--- | :--- | :--- |
| 语言/运行时 | **JDK 25** | 与现有环境一致；LTS |
| 框架 | **Spring Boot 4.x**（Spring Framework 7） | JDK 25 优先选 4.x；若生态未就绪，用 3.5.x + JDK 21 运行、25 编译，先做 1 天 spike |
| 持久层 | **MyBatis + Mapper XML** | 与团队规范一致；`#{}` 防注入；分页上限 |
| 数据库 | **MySQL 8.4 LTS** | 现有；utf8mb4；JSON 列存配置快照 |
| 迁移 | **Flyway** | 版本化 DDL，禁止手改生产 |
| 缓存/限流 | **Redis 7**（可选） | 仅 AI 限流/配置缓存；单机可先不做 |
| 容错 | **Resilience4j** | LLM 超时、熔断、重试（只读） |
| API 文档 | **springdoc-openapi** | `/swagger-ui` 仅内网 |
| 观测 | **Actuator + Micrometer** | p95、fallback 率、错误率、成本 |
| 测试 | **JUnit 5 + Testcontainers** | MySQL 集成测试 |
| 部署 | **Docker + Docker Compose** | 单服务 + MySQL；后续再上 K8s |
| 前端 | 不新增运行时依赖 | 现有 Vue3/Vite/Vuex；可选 Playwright E2E、Umami 分析 |

> **兼容性提醒**：Spring Boot 4 / MyBatis starter / JDK 25 的组合需先验证；若 MyBatis starter 暂未适配 Boot 4，优先“Boot 3.5 + JDK 21 运行”或“Boot 4 + Spring Data JPA”，不要为了版本号牺牲稳定性。

### 5.2 最小 API

| 方法 | 路径 | 用途 | 备注 |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/v1/sessions` | 开局登记（seed、模式、角色） | 匿名设备 id；返回 sessionId |
| `POST` | `/api/v1/records` | 上传单局结果 | 幂等 `requestId`；批量可选 |
| `GET` | `/api/v1/records/me` | 拉取个人记录 | 云存档时用 |
| `GET` | `/api/v1/leaderboard?mode=` | 排行榜 | 仅在有反作弊方案后开放 |
| `POST` | `/api/v1/banker/plan` | LLM 计划 | 800ms 超时；失败回退 |
| `GET` | `/api/v1/config` | 模式/参数/开关 | ETag + 版本号 |
| `GET` | `/actuator/health` | 健康检查 | 内网 |

### 5.3 数据表（草案）

```sql
-- 会话（可只保留最近 90 天）
game_session(
  id            CHAR(36) PRIMARY KEY,
  device_id     CHAR(36) NOT NULL,
  seed          BIGINT NOT NULL,
  mode_id       VARCHAR(32) NOT NULL,
  persona_id    VARCHAR(32) NOT NULL,
  started_at    DATETIME NOT NULL,
  KEY idx_device (device_id, started_at)
);

-- 单局结果（云存档/统计/排行榜）
game_record(
  id            CHAR(36) PRIMARY KEY,
  session_id    CHAR(36) NOT NULL,
  base_prize    BIGINT NOT NULL,      -- 分
  persona_bonus BIGINT NOT NULL,
  prize         BIGINT NOT NULL,
  decided_by    VARCHAR(16) NOT NULL,
  rounds        TINYINT NOT NULL,
  mode_id       VARCHAR(32) NOT NULL,
  persona_id    VARCHAR(32) NOT NULL,
  created_at    DATETIME NOT NULL,
  KEY idx_mode_prize (mode_id, prize DESC),
  KEY idx_device (session_id)
);

-- LLM 审计（不含 prompt 原文/玩家箱金额）
banker_ai_log(
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  session_id    CHAR(36) NOT NULL,
  round_no      TINYINT NOT NULL,
  model         VARCHAR(64) NOT NULL,
  prompt_ver    VARCHAR(32) NOT NULL,
  context_hash  CHAR(64) NOT NULL,
  plan          VARCHAR(16) NOT NULL,
  delta         DECIMAL(5,4) NOT NULL,
  latency_ms    INT NOT NULL,
  tokens_in     INT NOT NULL,
  tokens_out    INT NOT NULL,
  fallback      BOOLEAN NOT NULL,
  created_at    DATETIME NOT NULL,
  KEY idx_session (session_id, round_no)
);

-- 配置版本（远程配置）
config_version(
  version       VARCHAR(32) PRIMARY KEY,
  payload_json  JSON NOT NULL,
  active        BOOLEAN NOT NULL,
  created_at    DATETIME NOT NULL
);
```

- 金额一律 `BIGINT` 分，禁止浮点（与全局规则一致）。
- 不存玩家箱金额、不存完整 prompt；只存结构化计划与 hash。
- 保留期：会话/审计 90 天，聚合统计可长期；提供删除接口。

### 5.4 LLM 网关细节

| 项 | 方案 |
| :--- | :--- |
| 请求 | `{ sessionId, round, context: {...}, allowedPlans: [...] }` |
| 响应 | `{ plan, delta, lineKey, reason }`，JSON mode/结构化输出 |
| 校验 | 枚举、档位、台词白名单、长度；再跑上限校验 |
| 超时 | 800ms；熔断 30s；失败回退启发式 |
| 缓存 | `contextHash` → 结果，TTL 10 分钟；同局同轮不重复调用 |
| 限流 | 设备/IP 每分钟/每日；全局日预算 |
| 安全 | key 仅服务端；CORS 白名单；无自由文本输入；不记录原始输出 |
| 成本 | 每局 ≤9 次；优先缓存；可预取；超预算自动降级 |
| 模型 | 支持 JSON 输出的任意模型；provider 可替换；不绑定 LangChain |

**成本估算（量级）**：每次约 1k 输入 + 150 输出 token；10,000 局/日 × 9 次 ≈ 9 万次/日 ≈ 1 亿 token/日；按供应商单价 × token 计，缓存/预取可降一个量级。上线前先做日预算与降级开关。

### 5.5 反作弊与排行榜（如要做）

- 单机玩法**不需要**反作弊；本地记录作弊只影响自己。
- 排行榜三种方案：
  1. **不做服务端校验**：只做“本地最佳”，成本最低（推荐）。
  2. **服务端重放**：上传 seed + 操作序列，服务端用同一引擎重算；要求引擎逻辑单一来源（见下）。
  3. **服务端权威开局**：seed 由服务端发，客户端只上报结果；仍需校验操作合法性。
- 若选 2/3，**不要用 Java 重写引擎**（双份规则必漂移）。把 `src/views/game/services` 抽成同构 TS 包，Node 服务直接复用；Java 服务只做存储/鉴权/LLM 代理。若坚持 Java，必须用 golden tests 对齐两套实现，成本高，不推荐。

## 6. 前端需要的准备（不依赖后端）

1. **存储版本**：`dond.record.v2`，新增 `modeId`、`personaId`、`sessionSeed`；旧数据迁移默认 `classic`/`pragmatic`。
2. **特性开关**（构建时环境变量，便于灰度/回滚）：
   ```text
   VITE_FEATURE_MODES=true
   VITE_FEATURE_AUDIENCE=true
   VITE_FEATURE_PERSONA=true
   VITE_FEATURE_BANKER_PLANS=true
   VITE_BANKER_BRAIN=heuristic   # heuristic | remote（P2）
   ```
3. **API 客户端**（仅 P2）：`fetch` 包装，超时/取消/重试；失败静默回退，不阻塞游戏。
4. **不新增运行时依赖**：卡牌翻转/观众/建议用 CSS + 现有 Element Plus；避免为动画引库。
5. **埋点（可选）**：只上报匿名事件（模式、角色、是否接受、计划、fallback），批量 + 采样；不采集个人信息。

## 7. 部署与运维（若引入后端）

- 静态站：Nginx/CDN + HTTPS；缓存策略按文件名 hash。
- API：Docker 单实例起步；健康检查；滚动发布；环境变量注入密钥。
- MySQL：每日备份；慢查询日志；索引按 `mode_id/prize`、`session_id`。
- 观测：p95 延迟、5xx、LLM fallback 率、日 token/成本、计划分布；告警阈值。
- 安全：CORS 白名单、限流、输入校验、日志脱敏、依赖漏洞扫描；密钥不进仓库。
- 成本：小规模 2C4G API + 1C2G MySQL 即可；LLM 成本按预算上限控制。

## 8. 分阶段路线

| 阶段 | 内容 | 后端 | 判定 |
| :--- | :--- | :--- | :--- |
| **v1.5（现在）** | 卡牌/巨奖、观众、角色、启发式银行家、模拟调参 | 无 | 默认路线 |
| v1.6（可选） | 远程配置（静态 JSON→API）、轻量分析、云存档 | 可选 | 有运营/跨设备需求再开 |
| v2.0（触发） | LLM 银行家网关、审计、限流、A/B | 是 | AI 上线前必须先做 |
| v2.x（可选） | 排行榜/服务端重放 | 是 | 竞技需求明确再做 |

**决策门**：

- 没有“AI 上线/云存档/排行榜/热更新”中的一个 → 不启后端。
- 启后端时，先做**一个**最小服务（LLM 代理优先），不要一次性上微服务/消息队列/K8s。
- 任何服务端规则校验都必须复用前端引擎的单一实现，避免双份规则。

## 9. 风险与对策

| 风险 | 对策 |
| :--- | :--- |
| 过早引入后端，运维/成本上升 | 按 §4 门槛；静态站优先；离线可玩 |
| JDK 25 + Spring Boot 4 生态未适配 | 先做 spike；必要时 Boot 3.5 + JDK 21 运行 |
| LLM 延迟/成本/幻觉 | 800ms 超时 + 启发式回退；枚举输出；缓存/预算；服务端校验 |
| 排行榜作弊 | 不做竞技榜，或服务端重放；复用一个引擎实现 |
| 规则双份漂移 | 引擎保持 TS 单一来源；Java 只做薄服务 |
| 隐私/合规 | 匿名设备 id；不存 prompt 原文/玩家箱金额；保留期与删除接口 |
| 供应商锁定 | LLM provider 抽象；配置化模型；可切本地/国产模型 |

---

## 10. 建议（给决策者）

1. **v1.5 不引入后端**：四项优化全部前端可做，先验证趣味性与平衡。
2. **现在只做一件事为后端留口**：把 `BankerBrain` 抽成接口，启发式实现先跑；P2 再接远程。
3. **AI 上线前先做网关**：密钥、限流、超时、回退、审计、二次校验，一个都不能少。
4. **不要用 Java 重写游戏引擎**：如未来要服务端校验，复用同构 TS 引擎；Java 只做存储/鉴权/LLM。
5. **数据从简**：先 localStorage + 模拟脚本；有真实需求再上 MySQL 表。
